# mca.teros.remote

Teros Remote — operate a paired machine through an outbound WSS tunnel.
Spec: `docs/specs/remote/teros-remote.md`.

Install on a machine: `curl -fsSL https://get.teros.ai/remote.sh | sh`, then `teros-remote pair`
and paste the key into the app instance.

This directory is a **generated mirror** of the daemon's MCA definition
(`teros-remote/packages/mca`). The daemon is the source of truth for the tool
surface; the files here only tell the catalog and the executor what exists:

- `manifest.json` — hand-maintained (auth: `api-key` with the single user
  secret `TEROS_REMOTE_KEY`, which is where the user pastes the key printed by
  `teros-remote pair`; `multi: true`, one install per machine).
- `tools.json` + `i18n/en.json` — generated by `bun scripts/sync-remote-tools.ts`
  from the daemon's `packages/mca/tools.json`. Do not edit by hand; re-run the
  script after bumping the daemon (`--check` verifies they are in sync).

App instances of this MCA never spawn a container: `McaManager` routes their
tool calls through `RemoteDeviceGateway` (`/ws/remote`) to the paired daemon
(`executeToolViaRemote` in `mca-manager.tools.ts`). There is no `src/` here on
purpose — nothing runs on the Teros side.
